# Nexus Messenger

Сайт: https://alexasryan.github.io/mdrg/

React, TypeScript и Vite. Интерфейс мессенджера, локальная демо-переписка и WebRTC-звонки между вкладками одного браузера. Без настроенного Supabase данные не передаются между устройствами. Демо-аккаунты: `anna@demo.local` и `ivan@demo.local`, пароль `demo1234`.

## Разработка

Node.js 22.12+ (рекомендуется 24), npm.

```sh
npm ci
npm run dev
npm run check
npx playwright install --with-deps chromium
npm run test:browser
```

`npm run check` проверяет TypeScript, production-сборку и тесты backend. Браузерные тесты проверяют гостевой запуск, валидацию, вход/выход, обновление страницы настроек, независимые сессии двух вкладок, обмен сообщениями без дублей, мобильную ширину 320 px, несуществующие комнаты, приглашения и прямые звонки. Для WebRTC используются тестовые камера и микрофон Chromium; физические устройства и внешние сети этим не проверяются.

Демо-данные и хеши демо-паролей находятся в localStorage, сессия — в sessionStorage отдельно для каждой вкладки. Используйте тестовые данные и отдельный пароль. Это не серверная авторизация и не защищенный многопользовательский сервис.

## Публикация

Рабочая ветка: `nexus-messenger-web-app-164dd`. Workflow `.github/workflows/pages.yml` устанавливает зависимости из lockfile, собирает `dist`, запускает автоматические и браузерные проверки и публикует проверенную сборку через GitHub Pages Actions. После deployment проверяются опубликованные HTML, ресурсы и браузерные сценарии. Результаты доступны в GitHub Actions.

Workflow использует уже подключенный GitHub Pages и публикует `dist` через `actions/deploy-pages`; смена режима Pages через API не требуется. Старые шаблоны Jekyll и Webpack удалены, поскольку проект использует Vite. В репозитории также сохранен собранный корневой снимок для существующего режима публикации из ветки. При ручном переключении Pages на GitHub Actions публикация из ветки отключается.

Исходный HTML находится в `site/index.html`, компоненты — в `src/`, статические файлы — в `public/`. Корневой `index.html` и `assets/` — собранный снимок для совместимости с прежней публикацией из ветки; вручную их не редактируйте. Обновить снимок локально можно командой `npm run pages:sync` после сборки. В режиме Actions публикуется только `dist`, коммиты бота не нужны.

Для GitHub Pages задан base path `/mdrg/`. При другом имени репозитория задайте `VITE_BASE`. Маршрутизация использует hash (`/mdrg/#/settings`), поэтому прямые ссылки и обновление страницы не требуют серверных rewrites. Старые ссылки вида `/mdrg/call/id` перенаправляются через `404.html`.

## Подключение серверного режима

Пример публичных параметров находится в `.env.example`. Настройте собственный Supabase, примените миграции из `supabase/migrations/`, проверьте RLS и Storage для вашей модели доступа. В Supabase Auth задайте Site URL и разрешенный redirect URL `https://alexasryan.github.io/mdrg/`.

Для сборки нужны только публичный URL и публичный anon/publishable key. Не помещайте service-role key в frontend. Для подключения между разными устройствами также нужен доступный TURN-сервер с ограниченными по времени учетными данными. Реальный Supabase, доставка писем, восстановление пароля и звонки через внешние сети в рамках локальных демо-проверок не проверялись.
