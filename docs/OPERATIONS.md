# Настройки реального запуска

Проект Supabase: `mdrg` / `jyxbgmkuhcsjviqtuxom`, регион eu-central-1.
Сайт: https://alexasryan.github.io/mdrg/.

## Авторизация и письма

В [Auth → URL Configuration](https://supabase.com/dashboard/project/jyxbgmkuhcsjviqtuxom/auth/url-configuration):

- Site URL: `https://alexasryan.github.io/mdrg/`.
- Redirect URLs: `https://alexasryan.github.io/mdrg/**`.
- При локальной разработке отдельно разрешите `http://127.0.0.1:4173/mdrg/**`.

Плагин не предоставляет изменение Auth configuration; настройку необходимо сохранить в панели Supabase. Приложение использует PKCE, подтверждение почты и отдельный экран нового пароля после восстановления.

Для регистрации пользователей вне вашей команды настройте [свой SMTP](https://supabase.com/docs/guides/auth/auth-smtp) в Supabase. Встроенный почтовый сервис Supabase имеет ограничения по получателям и частоте отправки; он не заменяет производственную доставку писем. Секреты SMTP вводятся только в панели Supabase, не в GitHub и не в браузерную сборку. Рекомендуются CAPTCHA, ограничение регистрации и согласованные лимиты Auth после настройки домена почты.

Advisor сообщает, что [проверка скомпрометированных паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) выключена. Ее можно включить в панели Auth, если функция доступна в тарифе. Политики доступа к таблицам, приватным файлам и функциям проверены отдельно.

## Звонки

По выбору владельца запуск выполняется **без TURN**. Supabase передает сигналы, а браузеры устанавливают P2P-соединение с STUN. В некоторых мобильных, корпоративных сетях и при сложном NAT звонок не установится. Проверка двух изолированных браузерных контекстов не доказывает доступность всех внешних сетей. При подключении TURN выдавайте краткоживущие учетные данные сервером; постоянные секреты нельзя помещать в `VITE_*`.

В реальном режиме звонки доступны авторизованным участникам. Для входа по приглашению требуется регистрация/вход; возврат в приглашенную комнату сохраняется. Прямой звонок принимает только адресат. Чужой клиент не может записать сигнал от имени другого участника.

## Данные и обслуживание

- RLS включен на всех публичных таблицах. Изменения чатов, сообщений и звонков выполняются авторизованными транзакционными RPC; привилегированная реализация находится в неэкспонируемой схеме `private`.
- Прямой чат создается единожды для пары пользователей под блокировкой. Идентификатор исходящего сообщения сохраняется при повторе после сетевой ошибки.
- Файлы лежат в приватном bucket `chat-files` с лимитом 15 МБ. Ссылки подписываются после проверки участия и обновляются при загрузке сообщений. Аватары публичны, разрешены JPEG/PNG/WebP до 2 МБ.
- Realtime дополняется опросом при переподключении и возврате во вкладку. Удаления сообщений представлены как soft delete, чтобы событие проходило через RLS без раскрытия чужих строк.
- Cron `mdrg-maintenance` каждую минуту завершает просроченные звонки, удаляет устаревшие сигналы/участников и снимает устаревшее состояние online. История сообщений автоматически не удаляется.
- Настройте резервное копирование и мониторинг в соответствии с тарифом и нужным сроком восстановления. Бесплатный тариф может приостанавливать неактивный проект; для непрерывной доступности нужен соответствующий тариф. Платный тариф не подключался автоматически.

## Проверки

`npm run check` выполняет сборку и модульные тесты; `npm run test:browser` — проверку публичного входа и маршрутов. Демо-тесты запускаются только с явным `VITE_DEMO=true` при сборке и `MDRG_DEMO_TEST=1` при запуске Playwright.

`MDRG_TEST_FIXTURE=/путь/к/временному.json npm run test:integration` запускает 7 интеграционных проверок на Supabase: реальные сессии, единственный чат при гонке, идемпотентность, чтение/удаление только участниками, приватные файлы, Realtime, приватные звонки и запрет подмены сигналов. Файл должен содержать три временных аккаунта с полями `id`, `email`, `password`, `username`, `display_name`; секреты не коммитятся. Фикстуру создают только для отдельного тестового окружения или выделенных тестовых аккаунтов.

`MDRG_TEST_FIXTURE=… npm run test:browser` дополнительно проверяет обмен данными и аудиозвонок между независимыми контекстами браузера. В CI без тестовых аккаунтов эти проверки явно пропускаются. В ходе подключения проекта они выполнены на настоящем backend вручную через тестовый runner. Физические устройства, доставка почты и сети с обязательным TURN остаются отдельными проверками.
